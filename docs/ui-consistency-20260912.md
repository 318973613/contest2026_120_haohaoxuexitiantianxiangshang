## 二、这一轮做了三件事

### 1. 学习工具页视觉统一（主要工作）

**改之前的问题**（有截图对比，见第五节）：学习工具页是**不透明浅色整屏**，
没有壁纸、没有深色顶栏、tab 用的是 LVGL 默认浅色下划线样式，
下拉框是主题默认的灰框带阴影。放在主页旁边，一眼就是两个不同的产品。

**改之后**：完全复用主页的语言。

| 元素 | 改之前 | 改之后 |
|------|--------|--------|
| 页面底 | `COLOR_SURFACE` 不透明浅色 | `COLOR_BG` + 烘焙壁纸（与主页完全一致） |
| 顶栏 | `COLOR_SURFACE_ALT` 不透明 | `0x0a1b2f` @ OPA_60 + 白色 10% 下边框 |
| 返回键 | 蓝色方块按钮 | 与主页时钟胶囊同款（`0x071a2e` @ OPA_60，圆角 15） |
| 标签栏 | LVGL 默认（浅色下划线） | 与主页 tabbar 同款：`0x0a1b2f` @ OPA_80，选中项 `0x17314f` 底 + `0x75a0ff` 字 + 2px 顶边 |
| 内容区 | 直接铺在整屏上 | 白色半透明卡片（OPA_80，圆角 8，与 `create_panel` 同构） |
| 下拉框 | 主题默认灰框 + 阴影 | 白底、发丝边、圆角 6、无阴影 |
| 进度条 / 柱状图 | 默认极浅轨道 | 显式设置 `LV_PART_MAIN` 轨道色，柱子不再"空着" |
| 目标按钮矩阵 | 主题重边框 | 透明底 + 浅色 item，选中项蓝底白字 |

关键点：**壁纸只在 `g_compact_layout` 为真时加载**（`initialize_wallpaper()` 在非紧凑屏直接 return），
所以页面底色必须用 `COLOR_BG` 而不是深色字面量 —— 否则 1280x800 的检查会渲染出一块黑板。

### 2. 新增「学习报告」标签页（第三个标签）

学习工具从两个标签变成三个：**提醒中心 / 专注记录 / 学习报告**。

报告页内容（全部来自现有数据，**没有新增任何持久化**）：

- 今日专注（分钟）
- 完成轮次
- 连续天数
- 近 7 天累计 / 周目标（目标 × 5）进度条
- 学习任务待办 / 已完成（仅在该页可见时读任务文件）
- 一行次要信息：有异常时显示异常（未保存 / 未校时），正常时显示最佳一天与日均

设计上刻意不做缓存：每次刷新都从 `focus_stats` 重算，
这样报告、七日柱状图和主页计数**不可能互相矛盾**。

### 3. 新增「清除全部提醒」

提醒中心状态行右侧加了一个低调的「清除全部」胶囊按钮。
逐个调用 `cron_cancel_reminder()`（它只入队，由 cron 线程落盘），
状态行显示"已请求清除 N 条提醒"，而不是谎称列表已经空了；
没有提醒时显示"没有可清除的提醒"。

放在状态行而不是控件行，是为了在 480px 宽度下不挤压两个下拉框。

## 三、流水线修复（重要，必须记录）

这一轮第一次跑基线审计时**失败了**，原因不在代码，在流水线本身。记录如下。

### 问题 1：审计把"我们自己加的文件"当成"别人改的文件"

`audit_candidate.py` 原来对候选目录里每个文件都做 `实际树内容 != 基线` 判断。
基线是**继承基线**（202 个文件），所以：

- 第三轮新引入的 `study_focus_stats.c/.h` 不在基线里，`baseline.get()` 返回 `None`，
  第三轮同步前树里也没有这两个文件（`None == None`）→ 不报错；
- 第三轮同步之后这两个文件出现在树里 → `hash != None` → **误报为漂移**。

**修正**：把三个问题拆开回答，不再混在一起。

| 字段 | 含义 |
|------|------|
| `changed` | 候选内容和**当前树**不同 → 同步需要拷贝的文件（`sync_candidate.py` 用这个列表） |
| `added` | 路径不在继承基线里 → 是本轮/本线新增的，同步后出现属正常 |
| `unexpected` | 树和基线不一致 → 只有继承基线能回答，所以一轮结束后必须**基线前移** |

### 问题 2：基线是"一次性"的

`SOURCE_MANIFEST.json` 记录的是"这条工作线开始之前树的样子"。
第三轮同步之后，树**合法地**和基线不同了，所以第四轮必须前移基线。

新增 `rebaseline_candidate.py`，带硬约束：

> 前移前，每一个漂移文件都必须和**某个已归档候选轮次**里的副本**逐字节相同**。
> 手改的、或别的会话改的文件找不到归档匹配，前移直接失败。

这样既解决了问题，又不会把第三方改动"洗"进基线。

本轮验证结果：漂移 12 个文件，全部与 `img_backups/study-offline-candidate_20260912_151027/source/`
逐字节相同 → **确认漂移 100% 来自我们自己第三轮的同步**，没有第三方改动。

前移前的基线已保留，未删除：
`SOURCE_MANIFEST_before_20260912_152645.json` + `baseline_before_20260912_152645/`。

前移后审计结果：`baseline 202 / changed 1 / added 2 / unexpected 0`，
`changed` 正好只有 `study_terminal_main.c` 一个文件。
